# Unwritten · 可访问性（a11y）

本文定义 client 的可访问性目标、分工、各页面的具体做法，以及怎样测试。颜色与对比度的取值与判据见[主题与 token §5](./theme.md#5-语义-token颜色契约)，减少动态效果在[动效 §4](./motion.md#4-减少动态效果)。

## 1. 目标

- **满足 WCAG 2.2 AA。**
- **全部功能只用键盘就能完成。**
- **读屏软件可用：** macOS 上用 VoiceOver，Windows 上用 NVDA。
- **尊重系统偏好：** 减少动态效果、提高对比度、强制颜色模式，以及将来的减少透明度。

## 2. 分工

| 谁负责 | 负责什么 |
| --- | --- |
| Base UI | 它提供的组件（菜单、对话框、气泡、下拉选择、标签页、折叠区、提示、通知等）自带的角色、键盘操作、焦点圈定，以及关闭后焦点回到触发元素 |
| 我们 | 页面结构与地标、标题层级、路由切换时的焦点、宣告区、Base UI 之外的自定义部件（剧情流、提案卡、状态栏、手记）、通过 token 保证的对比度和焦点环、文案里的可读名称 |

使用 Base UI 组件时，不覆盖它的键盘行为和 ARIA 属性。确实需要改时，先看 Base UI 有没有对应的参数。

## 3. 页面结构

- **地标：**
  - 顶部工具行是 `header`；
  - 主内容区是 `main`，全应用只有一个；
  - 创作页的工作站面板是带名称的 `aside`；
  - 设置页的分区导航是 `nav`。
- **标题：**
  - 每页恰好一个 `h1`；
  - 标题级别按嵌套关系给，不为了字号而跳级。字号由 token 决定，和标题级别无关。
- **路由切换时：**
  - 更新 `document.title`；
  - 把焦点移到新页面的 `h1` 上（`tabIndex={-1}`）。读屏用户由此知道页面已经换了。
  - 启动后的第一页不移焦点。这时没有发生页面切换，读屏从文档开头读起；程序移过去的焦点在还没有任何操作时会被浏览器当成键盘焦点，标题上凭空出现一圈焦点环。

## 4. 键盘与焦点

- **Tab 顺序与视觉顺序一致。** 不用正数的 `tabIndex`。
- **焦点永远看得见：**
  - 所有可交互元素在 `:focus-visible` 时显示焦点环，宽度 `--uw-focus-ring-width`，颜色 `--uw-color-focus-ring`；
  - 焦点环用 `outline` 画，不用 `box-shadow`，这样在强制颜色模式下也能显示（§7）；
  - 不允许写 `outline: none` 却不给替代样式。
- **焦点不被遮挡。** 粘顶的工具行会盖住滚动到顶部的元素，所以滚动容器要设 `scroll-padding-block-start`，值等于工具行的高度 `--uw-size-toolbar`（WCAG 2.4.11）。
- **浮层：** Esc 关闭；对话框把焦点圈定在内部；关闭后焦点回到触发元素。这些由 Base UI 负责。
- **快捷键：**
  - 全局自定义快捷键带修饰键，不用单个字母，免得读屏用户和语音输入用户误触（WCAG 2.1.4）；
  - 每个快捷键都有对应的可点击按钮，快捷键只是加速，不是唯一入口；
  - 提示和菜单里显示快捷键（[i18n §9](./i18n.md#9-格式化)）；
  - 下表按 macOS 写作 ⌘，其他平台对应 Ctrl。

  | 快捷键 | 作用 |
  | --- | --- |
  | Enter / Shift+Enter | 在输入框里发送 / 换行（输入法组字时的处理见 [i18n §7](./i18n.md#7-中文排版)） |
  | ⌘1 … ⌘9 | 游玩页里选择第 N 个推荐行动 |
  | ⌘S | 游玩页里手动存档 |
  | ⌘, | 打开设置 |
  | Esc | 关闭当前浮层 |

- **只有图标的按钮**必须有 `aria-label`，文案走 i18n。

## 5. 颜色与对比

- **对比度由 token 保证。** 正文文字、大字号文字、控件边框和焦点环各自的对比度要求见[主题与 token §5](./theme.md#5-语义-token颜色契约)，由[主题检查](./theme.md#12-强制检查)逐项验证。
- **颜色不单独承载信息。**
  - 成功、警告、危险、信息都同时配有图标或文字；
  - 差异对比里的“删除”和“新增”，除了颜色，还要有删除线或文字前缀。
- 链接除了颜色之外还有下划线。正文里没有链接，所以只有界面受这条约束。

## 6. 尺寸、缩放与目标大小

- **布局尺寸优先用 rem。** 应用缩放（⌘+、⌘-、⌘0，由 desktop 调整 Electron 的缩放系数）时，版式等比放大。缩放到 200% 时不丢内容或功能（WCAG 1.4.4）。纵向滚动页面在等效宽度 320 CSS px 时能重排，并保留内容与功能（WCAG 1.4.10）。
- 阅读偏好里的正文字号可以单独调大，不影响界面（[主题与 token §4.2](./theme.md#42-正文与阅读偏好)）。
- **交互目标不小于 `--uw-size-target-min`（24px，WCAG 2.5.8）。** 主要操作用 `--uw-size-control-md`（32px）或更大。

## 7. 系统偏好

| 偏好 | 处理方式 |
| --- | --- |
| `prefers-reduced-motion: reduce` | 由动效 token 统一处理：去掉位移和缩放，只保留短暂的淡入淡出（[动效 §4](./motion.md#4-减少动态效果)） |
| `prefers-contrast: more` | 由主题 token 统一处理：提高次要文字和分隔线的对比、焦点环加粗（[主题与 token §8](./theme.md#8-提高对比度)） |
| `forced-colors: active`（Windows 高对比度） | 浏览器用系统颜色替换我们的颜色。为了让轮廓仍然可见：卡片、按钮、输入框始终保留一条边框，不需要显示时设为 `transparent`，而不是删掉；焦点环用 `outline`；图标用 `currentColor` |
| `prefers-reduced-transparency: reduce` | 浅色和深色主题没有半透明表面，这项偏好暂时无需处理；将来的半透明主题必须响应它（[主题与 token §6](./theme.md#6-材质预留给将来的主题)） |

## 8. 游玩页

游玩页是读屏用户停留最久的地方，单独设计：

- **剧情流：**
  - 每个回合是一个 `article`，用一个读屏可见、视觉隐藏的标题命名，例如“第 12 回合”；
  - 玩家的行动在两段剧情之间，前面加一个视觉隐藏的前缀“你的行动：”。
- **生成中：**
  - 正在生成的那个回合设 `aria-busy="true"`；
  - 生成中只展示等待状态。
- **新剧情到达：**
  - 宣告区播报“新的剧情已到达”；
  - 如果回应到达时玩家仍停在最新决定点，且焦点尚未离开行动区域，就把焦点移到新回合标题；
  - 如果玩家当时正在别处阅读，焦点不动，只播报。
- **推荐行动：**
  - 放在一个带名称的 `role="group"`（“推荐行动”）里，每个行动是一个按钮；
  - 开启“提醒已知后果”时，提醒文字通过 `aria-describedby` 关联到对应的按钮。
- **状态栏：** 是一个带名称的区域（“当前状态”），内容用 `dl` 列表。数值变化时不主动播报，读屏用户进入这个区域就能查看。
  - 有范围的数字栏目用 `<meter>`，可读的值带上范围和单位；
  - 阶段栏目读作“第 2 步，共 4 步：见过”，不读没到达的阶段名；
  - 清单栏目是嵌套列表，每一项的状态写成文字；
  - 本回合的变化标记是可读的文字，不只靠高亮；
  - 每个栏目的来历入口是按钮，名称里写明栏目，例如“查看备用钥匙的来历”。
- **澄清请求：** 宣告区播报问题。玩家仍在行动区域时，把焦点移到第一个选项；没有选项时移到回答框。
- **“回到最新”：** 是一个普通按钮，按下后焦点移到最新回合的标题。
- **手记：** 是列表。按“跳回原文”后，焦点移到原文的那一段（`tabIndex={-1}`），同时显示定位高亮。
- **换一种发展的比较：** 用 Base UI 的标签页在“原版”和各个候选之间切换。
- **插图：**
  - 画好的插图是一个按钮，名称是“放大查看插图”，`img` 的 `alt` 是画面说明（[插图与出图服务 §8](./image.md#8-镜头描述)）；
  - 占位设 `aria-busy="true"`，状态文字（“正在构思画面”“正在唤醒出图服务”“等待你完成授权”“排队中”“正在画这一幕”）可以读到；
  - 出图服务要求授权时，提示出现时经宣告区 `polite` 播报一次，不抢焦点；「打开授权页」「继续」是普通按钮，提示在唤醒结束前不自动消失；
  - 插图画好或画失败都不经宣告区播报，以免打断阅读；失败那一行的「重试」「不要这张图」是普通按钮，名称里写明是哪一张插图；
  - 大图是 Base UI 的对话框，画面说明作为对话框的描述，Esc 关闭后焦点回到插图按钮。移除插图时，焦点回到该图所属的正文段落。移除开场图时，焦点回到第一段；
  - 手记里的参考图缩略图 `alt` 写人物在主角口中的称呼。

人物参考组的每个位置都有可读的名称和状态。键盘可通过「选择图片」打开系统文件选择器。导入错误与对应位置关联，重试或替换仍在同一位置完成。

长剧情分段挂载时，手记定位先挂载目标再移焦点，当前焦点所在的回合保持挂载。读屏用户可通过带名称的加载前文入口继续访问更早的回合。

## 9. 创作页与工作站

- 向导的每一步是一个带标题的区域，标题级别是 `h2`。当前所在的步骤用 `aria-current="step"` 标出。
- 宽窗的工作站分隔条可聚焦，有名称和范围。方向键调整面板宽度；窄窗使用模态浮层，Esc 关闭后焦点回到打开按钮。
- **工作站的消息列表**不设为实时播报区，因为 AI 的回复是流式的，逐段播报会打断用户。回复完成后，宣告区播报“AI 已回复”；出现提案卡时，播报“有一张待确认的提案卡”。
- **提案卡：**
  - 是一个带标题的 `article`；
  - 卡上的问题是带标签的表单控件；
  - 确认按钮不可用时，在卡片正文写明原因，并通过 `aria-describedby` 关联按钮（[创作工作站 §5](./author-workstation.md#5-提案卡)）。
- **差异对比：** 修改前后用文字标出“删除”和“新增”，不只靠颜色。

## 10. 宣告区

- 全应用共用一个 `LiveRegion` 组件，分两个级别：
  - `polite`：大多数播报；
  - `assertive`：只用于阻断操作的失败，例如生成失败、保存失败。
- 宣告区的文案走 i18n。
- 同一件事只播报一次：不让组件状态的反复渲染重复触发播报。

## 11. 测试

- **组件测试：** 用 Vitest + Testing Library，每个共享组件都跑一次 axe-core 检查，并且用角色和名称查询元素（`getByRole`）。用角色查不到的元素，读屏软件也很可能找不到。
- **端到端测试：** 用 Playwright，每个页面在浅色和深色主题下各跑一次 `@axe-core/playwright`。
- **键盘走查：** 不碰鼠标，走完“新建作品 → 生成方案 → 采用开场 → 存入作品库 → 开始故事 → 行动三回合 → 存档 → 从存档另开”。
- **读屏走查：** 用 VoiceOver 走同一条流程，确认每一步都能听懂自己在哪里、发生了什么、下一步能做什么。

## 12. 不做的事

- **内置朗读。** 朗读交给系统的读屏软件和朗读功能，应用不自带语音合成。
- **专门的语音命令。** 语音控制靠标准控件和可读名称来点选，不另设一套语音指令。

## 13. 验收

| 从什么情况开始 | 操作 | 应当看到的结果 |
| --- | --- | --- |
| 任意页面 | 运行 axe 检查 | 没有严重和重大级别的问题 |
| 键盘操作 | 走完 §11 的键盘走查流程 | 每一步都能完成；焦点始终可见，没有被工具行挡住 |
| 开着 VoiceOver，在游玩页提交一个行动 | 等新剧情到达 | 听到“新的剧情已到达”，焦点落在新回合的标题上；生成过程中没有被逐段打断 |
| 开着 VoiceOver，在工作站让 AI 提出一张提案卡 | 等回复完成 | 听到“有一张待确认的提案卡”；能听到确认按钮为什么不可用 |

| Windows 开启高对比度主题 | 浏览作品库和游玩页 | 卡片、按钮、输入框的轮廓和焦点环都清晰可见 |
| 应用缩放到 200%，以及视口等效于 320 CSS px | 分别浏览所有页面，打开工作站与差异对比 | 内容和操作完整，纵向滚动页面无需横向滚动 |
