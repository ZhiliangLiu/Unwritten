# Unwritten 第四个里程碑：插图、出图服务与自建服务

**目标：** 沿着[第三个里程碑](./milestone-3.md)的路径，让故事在关键时刻有画面，并且同一个人物前后长得一样；出图服务和模型服务都可以自己部署在 Colab 上。

- **出图是基础能力。** core 通过协议接入出图服务，只看服务报告的能力，不认具体的服务。支持两种协议：自家的 Unwritten 图像协议，以及 OpenAI 图像接口（[插图与出图服务](./image.md)）。
- **插图定格故事里值得看的瞬间。** 玩家选择本局出图后，开场、人物动作与互动、玩家行动的可见后果、线索和环境变化都可以配图。正文提交后才开始画，每张图只使用该位置已经揭晓的内容。模型默认按画面选比例，用户选择分辨率档位。
- **同一人物前后可辨认。** 作者可以生成或从本机导入固定人物的基础参考组，玩家可以在开局选主角参考。每次出图按当时可见的身份和镜头取用参考，同一人物换装时沿用原基础组。
- **ComfyUI 是独立服务。** `plugins/comfyui/` 用 Qwen-Image-2.1 实现 Unwritten 图像协议。真实出图用自有 GPU 或满足部署前提的 Colab 验证，Colab 另走接入和重连检查。见[插件](./plugins.md)和 [ComfyUI 插件](./comfyui-plugin.md)。
- **Colab 上的部署只写一份。** `selfhost/colab/` 负责资源检查、Drive、Tailscale、访问控制和空闲释放，服务启动前卸载 Drive。ComfyUI 插件和 Strata 都只写自己的准备和启动步骤（[Colab 宿主](./colab-host.md)）。
- **出图服务可以按需启动。** 配了启动器的出图服务平时关着，进入开了插图的开局或有图要画时，core 通过启动器唤醒它；连续空闲到设定的分钟数，服务自己关闭。`plugins/colab-launcher/` 在 Mac 上用 Colab CLI 开关运行时（[插图与出图服务 §12](./image.md#12-按需启动)、[Colab 启动器](./colab-launcher.md)）。
- **Strata 作为自建模型服务。** `selfhost/strata/` 用 Strata 运行 Qwen3.8-Flash-Next 的 Q2_0，对外只经一层网关。core 把它当作普通的自定义端点，一行不改（[Strata 自建模型服务](./strata.md)）。

维护者在本机运行 desktop 的开发模式或打出的包，可接 ComfyUI 插件或 OpenAI 兼容图像接口，也可以把任意用途分给 Colab 上的 Strata。纯文字路径沿用[第三个里程碑](./milestone-3.md)的创作、开局和续写体验。

## 作者和玩家能做什么

| 环节 | 可交付的体验 |
| --- | --- |
| 配置出图服务 | 测试连接、查看出图能力和用量，确认数据接收方后主动开启自动出图。见[出图服务的配置](./image.md#2-出图服务的配置) |
| 作者定形象与画风 | 预览默认画风，为固定人物导入或生成正面，按需补齐其他视角并采用，在试玩中看效果。见[创作流程 §2–5](./authoring-flow.md#2-写背景只补自己在意的设置) |
| 开局和游玩 | 选择本局插图或纯文字，按需选主角参考、比例偏好和分辨率。读到图时可以放大、保存、重画或移除，失败后按张重试。见[游玩流程 §2.1](./gameplay-flow.md#21-插图) |
| 按需启动出图服务 | 在 Mac 上常驻启动器，在设置页给出图服务填启动器地址和令牌，设空闲分钟数。进入开了插图的开局时服务自动唤醒，需要授权时按提示在浏览器里完成。见[游玩流程 §2.1](./gameplay-flow.md#21-插图) |
| 自建模型服务 | 在 Colab 上运行 Strata，在设置页把它添加为自定义端点，测试连接后分给任意用途。见 [Strata 自建模型服务 §9](./strata.md#9-在-unwritten-里接上) |

## 实现顺序与检查点

1. **外发请求的统一出口。** 把 `llm` 模块里不跟随重定向的 `fetch` 封装抽成 `net` 模块，`llm` 改为经过它。重定向的验收用例照常通过。[插图与出图服务 §5.2](./image.md#52-外发请求) · [LLM 端点 §3](./llm-endpoints.md#3-key-的来源与保护)
2. **出图服务的配置。** `providers.json` 升到版本 2，新增 `imageServices` 和 `image`；设置页的「出图服务」一节；令牌生成；`app_settings` 里的插图开关。[插图与出图服务 §2](./image.md#2-出图服务的配置)
3. **Unwritten 图像协议。** `image` 模块的协议客户端、伪服务和一致性测试；扫描源码、禁止出现插件专属名字的测试。[插件 §2–3](./plugins.md#2-边界) · [插图与出图服务 §3](./image.md#3-unwritten-图像协议)、[§5](./image.md#5-image-模块)
4. **OpenAI 图像接口。** 文生图与编辑两条路径、尺寸与能力预填、错误映射。[插图与出图服务 §4](./image.md#4-openai-图像接口)
5. **形象与段落可见性。** 可选的形象与插图标记、开局行的插图设置、按原回合和段号取场景材料。[插图与出图服务 §6.1](./image.md#61-形象) · [数据模型 §5](./data-model.md#5-可见性规则) · [回合循环 §6](./turn-loop.md#6-校验与保存)
6. **参考组和插图流程。** 导入或生成各视角，采用并冻结参考组。登记插图后按镜头取参考，做正文出图、重试、重画与取消。[插图与出图服务 §6.2–8](./image.md#62-人物参考组)
7. **存储与交付。** 图片按内容存一份，数据库记录归属、采用快照和实际使用的参考。补齐回收、鉴权取图和变更通知。[插图与出图服务 §9–11](./image.md#9-存储)
8. **界面。** 设置页、方案里的参考组、开局时可选的主角参考、游玩页的占位与大图、手记缩略图。[创作流程 §3](./authoring-flow.md#3-确认故事方案再生成开场) · [游玩流程 §2.1](./gameplay-flow.md#21-插图)
9. **Colab 宿主。** 宿主与服务的约定、资源检查、Drive 的复制与卸载、Tailscale 接入、看护循环与空闲释放、伪 Colab 与 pytest，以及 `plugins/` 和 `selfhost/` 共用的 Python 工具链（uv、ruff、pytest、lefthook）。[Colab 宿主](./colab-host.md) · [插件 §6](./plugins.md#6-仓库里的插件)
10. **ComfyUI 插件。** 包装服务、四份工作流模板、按 GPU 型号的分辨率清单、模型锁定、对宿主的约定、笔记本、README、伪 ComfyUI 与 pytest、CI 里的一致性测试。[ComfyUI 插件](./comfyui-plugin.md)
11. **Strata 自建模型服务。** 版本与模型锁定、运行参数、网关与自检、对宿主的约定、笔记本、README、伪 Strata 与 pytest；扫描源码的测试加上 `strata`。[Strata 自建模型服务](./strata.md)
12. **按需启动。** `image` 模块的启动器客户端、伪启动器和一致性测试；预热、按需唤醒、等待用户操作、超时与失败；设置页的启动器配置和空闲分钟数；游玩页和创作页的唤醒提示。Colab 启动器、伪 colab 命令与 pytest，以及宿主「由启动器启动」的入口和状态行。[插图与出图服务 §12](./image.md#12-按需启动) · [Colab 启动器](./colab-launcher.md) · [Colab 宿主 §8.1](./colab-host.md#81-由启动器启动)
13. **端到端与评测。** 浏览器模式用伪服务覆盖下面的产品验收。用真实模型检查选图时机、形象、动作与人物互动的准确性、多人画面中的身份一致性。Colab 上的接入与重连按 [Colab 宿主 §14](./colab-host.md#14-验收)、[ComfyUI 插件 §13](./comfyui-plugin.md#13-验收)、[Colab 启动器 §10](./colab-launcher.md#10-验收) 和 [Strata 自建模型服务 §14](./strata.md#14-验收) 执行。

1–4 和 9 可以并行，10、11 在 Colab 上的部分依赖 9。插件侧先用真实工作流对照「正面＋全身」与「再加斜侧脸」，验证多人互动、换装和线索近景，记录出图耗时。5–8 先用伪服务从本机导入参考走到游玩出图，随后用真实服务复验。11 不依赖插图那条线，可以和 1–8 并行。12 依赖 3、9 和 10。

## 留给后续的能力

| 能力 | 推迟的理由 |
| --- | --- |
| Gemini、A1111、阿里云百炼等其他协议 | 可以在服务前面加一层实现 Unwritten 图像协议的代理来接入，core 不用改 |
| 服务端原生画风（例如画风对应到服务器上的 LoRA） | 画风预设要和服务器上装的模型一一对应，复杂度明显上升 |
| 手动「画这一幕」、插图的图集与导出 | 自动插图先跑一段时间，看缺不缺这些 |
| 生成进度的百分比 | OpenAI 图像接口不报告进度，占位保持安静 |
| 游玩中途改画风 | 一局之内保持统一的画风 |
| 单独删除一局及其图片 | 图片清理已按引用处理，单局删除入口和确认流程另做 |
| 模型服务离线时自动切换端点 | 中途换模型，文风和工具调用的稳定性都会变；先由用户在设置页改用途分配 |
| 模型服务的按需启动 | 回合不能停下来等冷启动，还要改模型调用的超时规则；出图可以降级，先只给出图服务做 |
| 一个 Colab 运行时同时跑出图和模型服务 | 单卡通常放不下两份权重，两边会争抢显存 |

## 验收

| 从什么情况开始 | 操作 | 应当看到的结果 |
| --- | --- | --- |
| 未配置出图服务，或玩家选了「本局纯文字」 | 分别创作、开局并提交行动，让模型省略形象并返回无效的插图段号 | 正文和选项照常提交，本局无插图占位，对出图服务的请求为零 |
| 设置页 | 添加一个 Unwritten 图像协议的服务并生成令牌，离开页面再回来 | 令牌只在生成时显示过一次；之后只显示「已配置」和来源 |
| `providers.json` 是版本 1 | 启动应用，添加一个出图服务 | 原有的模型配置都在；文件变为版本 2，旧文件存为 `providers.json.bak` |
| 已选好出图服务，自动出图尚未开启，开场有已公开的初始处境 | 开局一次，完成开启确认后再选插图开局 | 第一次没有自动出图请求。确认页分别列出接收正文片段和接收参考图的服务，第二次出现插图占位 |
| 服务支持横图和竖图的 1K 档位 | 用自动比例玩到两位人物并肩互动，再玩到主角沿梯子向上爬，让镜头模型分别选横图和竖图 | 请求比例符合两个镜头，都使用各自比例的 1K 实际尺寸。画框展开和到图时阅读位置保留 |
| 服务支持 720 和 2K，当前镜头用同一固定比例 | 各开一局，分别选 720、2K，生成同一镜头 | 两局请求和保存的实际像素符合各自档位。档位变化只改变像素，比例保持原选择 |
| 开场选择 9:16，玩家处于窄视口或放大到 200% | 等插图占位展开并填图 | 画框不超过阅读区可见高度的一半。图片保持原比例，正文可见，画框展开时阅读位置不动 |
| 旧插件只报告比例，或 OpenAI 兼容服务只支持固定尺寸 | 查看设置并开局 | 界面仅提供可用档位。旧插件仍能按比例出图，请求没有显式尺寸 |
| 没有出图服务，作者手边有一张正面图 | 从人物卡导入并采用，再重新打开作品 | 正面图仍可查看。其余视角可以留空，导入期间没有外发请求 |
| 作者已经用旧参考开过一局 | 在编辑中替换正面，采用后再开一局，同时重画旧局的图 | 新局按场景取用新组的视角，旧局还能使用原参考 |
| 玩家在开局页选定了主角预览的正面，其他视角仍在生成 | 立即开始故事，等首次主角入画 | 开局不等待未完成的任务，主角图使用选定的正面 |
| 插图标在第 2 段，第 5 段才摘下面具并揭晓称呼 | 等插图到达，再从当前路线重新打开这一回合并重画第 2 段的图 | 提示词、参考图和画面说明只使用第 2 段可见的伪装和称呼 |
| 作者为两位固定人物选了基础参考组，真实 ComfyUI 服务就绪 | 试玩一段递钥匙又收手的互动，再画其中一人换装后的互动 | 维护者对照参考能认出两人。图中看得出谁在递钥匙、谁收回了手，换装前后角色仍可辨认 |
| 玩家在一段正文末尾面对尚未作出的选择 | 先读眼前的局面，再选择扳下闸杆让候船厅恢复照明 | 选择前的画面没有点亮大厅。灯光变化只出现在行动已经生效的段落之后 |
| 正文只露出怀表里的一小截齿轮，线索的来历稍后才揭晓 | 查看提示词和实机生成的近景 | 画面聚焦眼下可见的细节，说明与提示词不透露线索的来历 |
| 服务离线，多个回合的插图失败 | 继续读并提交行动。服务上线后重试其中一张图 | 正文正常推进。只有选中的图发起生成，其余失败状态和阅读位置保留 |
| 一张插图已完成，另有插图在排队和生成 | 关闭自动出图后，等待运行中服务返回结果 | 已完成的图仍能放大和保存。排队请求不发出，迟到的结果不会出现在正文里 |
| 玩家正在往上读前文 | 分别等两处占位填图和失败收起，再重试失败的图 | 当前正文锚点和键盘焦点保持可用 |
| 手记里有一位只听说过的人物 | 打开手记 | 他的条目没有参考图缩略图 |
| 使用支持参考图的 OpenAI 兼容服务 | 玩到一个带参考人物的关键场面 | 走编辑接口，实际宽高的图片完整放进原框。服务拒绝时显示原因 |
| 两部作品引用同一张参考图 | 分别删除作品并运行图片清理 | 第一部删除后，另一部仍能读图。最后一处引用消失且经过清理保护期后，文件被回收 |
| 系统开启减少动态效果 | 等一张插图生成并到达 | 占位不呼吸，图片直接淡入，没有位移 |
| Colab 上的 ComfyUI 和 Strata 都已就绪 | 在每个运行时里列出 `/content/drive`，再从 Mac 访问两个服务地址 | Drive 都已卸载。两个地址都能访问，节点之间互相连不上 |
| Strata 已作为自定义端点接上，并分给 narrator | 开局并连续玩几个回合，包括一次需要工具调用的回合 | 回合正常提交，和用云端模型时的流程一样 |
| ComfyUI 服务配了 Colab 启动器，运行时关着 | 进入一个开了插图的开局，按提示完成 Drive 授权 | 占位先显示「正在唤醒出图服务」，授权后服务就绪，开场图画成。正文一直可读 |
| 服务由启动器唤醒，之后没有出图请求 | 等过设置页设的空闲分钟数，再玩到一个标了插图的回合 | 运行时已经释放；这张图触发再次唤醒，并在服务就绪后画成 |
| narrator 分给 Strata，Colab 运行时被回收 | 提交行动，重新运行笔记本后再重试 | 先提示连不上模型服务；重试后回合提交成功，已有回合不受影响 |
