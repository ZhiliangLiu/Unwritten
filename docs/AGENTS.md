# docs/ 写作规范

本目录是 Unwritten 的设计权威。代码是设计的兑现；两者冲突时，先改文档，再改代码。

## 1. 文档分工

每份文档详写本领域的契约。涉及别的领域时，只写和本领域有关的那一句结论，并链接到详写它的文档。

## 2. 写作原则

文档只描述**系统应有的样子**，以及**为什么这样设计**，不记录设计是怎样演变过来的。

- **直接改成新的样子。** 不标注“新增”“修正”“补齐”。改完之后，读者看到的就是唯一的当前设计。
- **不写前后对比。** 不出现“之前是 X，现在改成 Y”“原名 X”“早期草稿”这类叙述。设计判断用现在时直接陈述：结论是什么，理由是什么。
- **保留“为什么”。** 动机、权衡、边界和不做的事是文档的核心价值，写成“因为 A，所以 B”。
- **不留进度标记。** “已实现”“待实现”“讨论中”不进设计文档。
- **不写版本和阶段。** 不写“首版”“第一版”“v0.x”“原型阶段”，也不写“初始值，以后再调”。可以调的数写成“默认值，可配置”。
- **借鉴来源写在用到的地方。** 借鉴公开项目时，写明项目和文件路径，例如“thinkrail `packages/server/src/agent/customEndpoints.ts`”，不单独开一节“借鉴”。本机的私有项目不写进文档，读者看不到它们。
- **技术文档末尾的两节固定格式。** 技术文档指本目录下除本文件和两份产品流程文档以外的全部文档。
  - “不做的事”：写清不做什么、为什么。tech-stack.md 用“不选的方案”代替，因为它要说明的是没有选哪些库、为什么。
  - “验收”：一张三列表，列名是“从什么情况开始 / 操作 / 应当看到的结果”。
- **产品流程文档不受上一条约束。** [authoring-flow.md](./authoring-flow.md) 和 [gameplay-flow.md](./gameplay-flow.md) 写作者和玩家看得见的体验，验收的列名按体验的写法来，不强求三列。

## 3. 审计

只审计**本次改动的行**，不顺带审计其他内容。

- **不写**日历日期、任务号、提交哈希和个人裁定。
- **数字分两档。**
  - **构成契约的值**（默认值、上限、窗口、阈值）保留，并写明它在哪里配置。
  - **单次样本值**（某次运行的 token 数、某次测量的耗时、某批样本里的命中比例）改成量级加机制。例如“总额 393,216 被吃到 401,449”应写成“总额会被吃穿”。

  判别方法：这个数字变了，有没有代码或配置跟着变？没有的就是样本。
- **用户作品的内容不进文档。** 示例里的故事、人物名、对白一律虚构。
- **记录过程的文档不放进 `docs/`。** 凡是本质上在记录评审、任务拆解或验收过程的文档，都不属于这里。
- **新增内容前先搜一遍同样的结论。** 已经有的，优先更新、合并或删除旧表述，不按时间顺序追加“补记”。

**审计是改句子，不是换词。** 批量替换只能改字面，改不了语义，会留下三种残留：

- 删掉标识符后剩下的残句，例如“在  之前”“（）”；
- 只剩一个字的括注，例如“（补）”“（定案）”；
- 换了说法但没处理实质，例如把“实测”换成“验证”，数字却原样留着。

所以：不对 `docs/` 做全局整词替换；批量删除之后，逐条读每一处命中，把整句改写成现在时；带数字的句子换个措辞不算处理完，要按上面的两档判断。

提交前，对本次新增的行按顺序扫三遍，命中后逐条判断：

```bash
# 本次改动新增的行（暂存和未暂存都算），输出「文件:行号: 内容」
docs_added() {
  git diff HEAD -U0 -- 'docs/*.md' ':!docs/AGENTS.md' | awk '
    /^\+\+\+ b\// { file = substr($0, 7) }
    /^@@/ { split($3, a, /[,+]/); line = a[2] }
    /^\+[^+]/ { print file ":" line ": " substr($0, 2); line++ }'
}
# 1. 日期、哈希、版本与过程叙事
docs_added | rg '20[0-9]{2}[-年]|\b[0-9a-f]{7,40}\b|此前|曾经|本次修正|补记|首版|第一版|v0\.[0-9]|原型阶段|以后再|待实现|已实现|讨论中'
# 2. 删除标识符后留下的残句与单字括注
docs_added | rg '，\s[^\s|]|（\s|[^\s|]\s）|（）|（(补|补充|定案|修订|落地|修正)）'
# 3. 一次性读数：关键词后 80 字内带数字的句子，逐条按两档判断
docs_added | rg '(实测|测得|运行记录|样本)[^。｜|]{0,80}[0-9]'
```

刚新建、还没有提交过的文档不在 `git diff HEAD` 里，要整份扫描：把 `docs_added` 换成 `rg -n <同一条正则> docs/<文件名>`。

## 4. 中文母语感

判据很朴素：**念出来像不像中国人说话**。文档是中文写作，不是英文规格书的译文。

### 4.1 术语对照表

同一个概念在全仓只用一个词，不在同义词之间摇摆，因为读者靠词形认概念。

**工程用词：**

| 概念 | 用词 | 不要写 |
| --- | --- | --- |
| guard（写入前的校验） | 守卫 | 保护措施、防护逻辑 |
| gate（拦住流程继续的检查） | 闸门 | 关卡、检查点 |
| invariant | 不变量 | 恒定条件、不变式约束 |
| race condition | 竞态 | 竞争条件、并发冲突 |
| idempotent | 幂等 | 重复调用安全的 |
| stale | 过期 | 失效的、不新鲜的 |
| snapshot | 快照 | 状态镜像、瞬时副本。领域里只用于“试玩快照” |
| degrade（这件事做不成，退而求其次） | 降级 | 优雅处理、容错 |
| fall back（换一条路径拿到同样的东西） | 回落 | 兜底、fallback 方案 |
| single source of truth | 单源 | 唯一数据源、真实来源 |

“回落”和“降级”不是同义词：回落是换一条路径拿到同样的东西，降级是这件事做不成、退而求其次。混用会让读者判断不出后果。

**领域用词：**

| 概念 | 用词 | 不要写 |
| --- | --- | --- |
| 产品的使用者 | 用户（作者和玩家的统称） | |
| 写故事的人 | 作者 | 创作者、编剧 |
| 玩故事的人 | 玩家 | 读者；也不用“用户”单指玩家 |
| 一部可以游玩的故事 | 作品 | 剧本、游戏 |
| 作品的一份副本 | 版本：草稿、试玩快照、发布版本 | 修订版、快照版 |
| 每次开局的第一段剧情 | 开场 | 第一幕、开头 |
| 从开场开始的一次经历，可以包含多条路线 | 开局 | 周目、存档 |
| 玩家的一次行动加上 AI 的完整回应 | 回合 | 轮、步 |
| 开局里一条连续发展的线 | 路线 | 分支线、存档线 |
| 手动留下的决定点 | 存档 | 书签、快照（“试玩快照”是作品的版本，不是存档） |
| 换一种发展时生成、等待选择的回应 | 候选 | 备选、草案 |
| 作者写下的世界设定 | 作者设定 | 正典、canon |
| 作者折叠起来、玩家要靠剧情发现的设定 | 幕后设定；其中的条目叫幕后身份、幕后事件等 | 隐藏设定、剧透。“隐藏”作动词时不受限，例如“隐藏关系数值” |
| 谁知道什么 | 知情 | 认知记录 |
| 人物被谁怎样称呼 | 称呼 | 昵称；泛指时也不用“别名” |
| 最新段落下方的当前状态 | 状态栏 | 面板、HUD |
| 自动整理、可跳回原文的已知经历 | 手记 | 日志、笔记 |
| 界面一侧和业务逻辑一侧的组成部分（全部四个组成部分见[架构总览 §1](./architecture.md#1-四个组成部分)） | client、core | 前端、后端、sidecar（描述其他产品时不受此限） |
| 游玩时写剧情的模型用途 | narrator | 叙述器、旁白模型 |

### 4.2 句式黑名单

直接陈述当前设计，避免以下写法：

- **“应 / 应该 / 均应”堆叠**：改成现在时陈述句。验收表固定的列名“应当看到的结果”不算在内。
- **“对 X 进行 Y”“实现了 Y”**：直接用动词。
- **“使得”和多层定语**：拆句，先写动作，再写结果。
- **“具有……性”“……的决策”**：改回动词或形容词。
- **“是必要的”“值得注意的是”**：删掉空壳，直接写必须做什么、不做会怎样。
- **被动句堆叠**：有施事就写施事，没有就用无主句。

> **反例**：所有存档均应通过路线进行归属管理。
>
> **改写**：每个存档都属于一条路线。

## 5. 链接与章节编号

- 引用其他文档的章节时，写成带锚点的链接，例如 `[回合循环 §6](./turn-loop.md#6-校验与保存)`。
- 锚点按 GitHub 的规则由标题文字生成，**改标题就会改锚点**。改了标题或章节编号后，运行 `node scripts/check-doc-links.mjs`。
  - 它检查 README、`docs/`、`tasks/` 和全仓所有 AGENTS.md 里的相对链接：目标文件要存在，锚点要能对上目标文件里的某个标题。
  - 它会跳过不属于本仓库内容的目录：依赖、构建产物、`.data/`、`.turbo/`。`.claude/` 也跳过，因为 worktree 建在那里，每个都是整份仓库的副本。
  - 可以传入另一个目录作为仓库根，例如 `node scripts/check-doc-links.mjs <样例目录>`，用来拿样例测试脚本本身。
- 重排章节时，正文里指向旧编号的“§N”要一起改掉，可以用 `rg -n "§[0-9]" docs/*.md` 自查。
