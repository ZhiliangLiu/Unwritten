# Unwritten · 创作流程

**产品体验设计 · 作者视角**

作者从一段背景出发，在本机创建可以反复游玩的文字冒险。作者决定世界里哪些事成立、哪里留给玩家选择；AI 补全设定、演出剧情并记住每条路线的经历。作品可随时切回修改，作者和玩家都无需手动维护故事中出现的每个人物或地点。

**最短路径：本机作品库 → 写背景 → 确认故事方案 → 预览并采用开场 → 存入作品库。** 试玩和补充设置都可以按需进入。作品存为可玩后，按[游玩流程](./gameplay-flow.md)进入。

## 1. 从作品库新建，或接着上次的工作

| 作者眼前的情况 | 入口 | 操作后的体验 |
| --- | --- | --- |
| 第一次进入，或想做另一部作品 | 新建故事 | 看见背景输入框。已有作品可以继续游玩。 |
| 写过背景、改过方案或生成过预览 | 继续创作 | 回到这部草稿上次所在的步骤，保留输入、已确认的方案和已采用的开场。 |
| 作品已可玩 | 编辑作品 / 开始故事 | 前者打开创作稿，后者进入正式游玩。有进度时可直接续玩。 |
| 可玩作品还有修改草稿 | 继续编辑 | 此时不显示「编辑作品」。作者可以接着修改；作品库同时提供上次保存的可玩开场。 |

每部作品有自己的草稿、试玩和正式游玩进度。人物关系、谜题线索或任务进度按创作意图选用；即使只写背景，也能走完同一套创建流程。作品卡用标题和玩家可读的简介帮助辨认，作者没起名时可以先用背景首句辨认草稿。

## 2. 写背景，只补自己在意的设置

首屏只要求一段背景。起笔提示是「玩家是谁？身在何处？眼前发生了什么？」写下一项也足以点「生成故事方案」。作者可以粘贴完整设定，也可以写一句「末班渡轮停航前，你遇见了一个坚持等下一班船的人」。离开后能找回已写的草稿。

「补充设定」可在生成前展开，也可以等看到方案再调整。背景中已经明确的身份、关系、期限直接带入对应位置。下表列出默认呈现；作者有明确设定时，以作者设定为准。为让只写背景的人也能继续，故事方案默认预选「固定主要角色」和「只显示行动」，作者可在确认前改选。

| 作者能设置什么 | 可以怎样决定 | 未补充时或在预览中的表现 |
| --- | --- | --- |
| 世界及即兴发挥范围 | 写下时代、地点、世界规则，以及哪些细节欢迎 AI 创造 | AI 以背景为依据补全，方案概述它对世界的理解。 |
| 玩家主角 | 固定身份、初始关系、已知信息；明确哪些项目交给玩家填写 | AI 可提议一个能直接行动的身份。只向玩家询问作者主动留出的项目，没留项就直接开场。 |
| 主要人物 | 逐部选择「固定主要角色」或「每次新开局生成」。可写人物习惯、关系边界、希望发展的感情线，以及人物看起来的样子 | 固定模式预览具体人物，AI 可以为作者留空的形象提供建议。每局生成模式预览角色在故事里的作用和一次相遇样例。新开局使用所选模式，读档与分线保留已有角色。 |
| 秘密与知情范围 | 写谁知道什么、玩家凭什么可以发现、哪些真相在所有路线中成立 | AI 拟定的秘密、幕后事件及潜在结局在作者方案里默认折叠。人物姓名、简介和状态栏示例也按各自视角显示，作者可以保留悬念完成创作。 |
| 叙事与开场 | 指定作品语言、基调、视角、段落节奏或对白风格；开场可由 AI 起草、按指定情境写，或采用作者原文 | 作品语言跟随背景所用的语言。可先尝试第二人称、每段停在一个有意义的决定点。每部作品最终采用一个开场。 |
| 行动与提示 | 指定行动更偏交谈、观察或取舍；逐部选择「只显示行动」或「提醒已知后果」 | 预览同一个选择在本作品中的样子。提醒可以点明已知时间冲突，实际结果留给剧情。推荐项和自由输入都可用。 |
| 关键场面、进度和结局 | 可写「满足什么条件时，发生什么」以及何时结束；也可全部留白 | 同一作品里的不同路线可能触发不同场面。期限首先是一个世界事件；作者把它指定为结束条件时，才在此收束。 |
| 初始状态栏 | 用一句话写玩家要关注哪些事，以及每一栏用数字、阶段、清单还是文字显示。数字可以给出范围和单位，阶段按先后写出每一步，清单适合放约定、线索和随身物品 | 先预览开局，再看一次变化后的示例。未指定时，从已经明确的时间、地点等少量信息起步。 |
| 插图 | 配了出图服务时出现。选一个默认画风，或写一句自己的画风；「预览画风」用固定题材的示例图呈现效果 | 示例图只供选画风。保存的画风作为新开局的默认值，玩家可以在开局时改选。 |

**三处可以交代给 AI 的写作要求。** 「补充设定」提供三项自由文本，和背景一起自动保存：叙事要求（视角、人称、节奏、对白风格）、内容边界（哪些内容不出现）、即兴范围（哪些设定绝不改、哪些细节随 AI 补）。背景是故事世界里成立的事，这三项是怎么讲、讲到哪、能改到哪。它们原样进入开场和之后每一回合，留空时不加任何限制，也不限长度：写得越具体，AI 越照着写；写得过长，会挤占更早回合和人物索引的空间。

**设置状态栏时，作者能检查四件事：** 栏目叫什么、开局显示什么、何时变化、玩家何时能看见。例如「双方约定」开局为空，对方答应后才出现。阶段栏目里，玩家只看得见已经到达的阶段名，后面的阶段只显示还剩几步，所以阶段名可以写得直白，不用担心剧透。「隐藏关系数值」只影响呈现，角色仍会记得玩家做过的事。游玩中若新增了值得跟踪的事，AI 可以扩展栏目；作者标为幕后的信息在新栏目中同样受保护。

## 3. 确认故事方案，再生成开场

1. **看方向。** 点击「生成故事方案」后，先看到玩家身份、主要人物或角色位置、故事基调和开场处境。作者能分辨哪些来自自己的背景，哪些是 AI 的建议。题材和关系等留白可以由 AI 补齐。人物形象只写当时看得见的样子。固定人物的卡片可以展开「人物参考」，按需选定一组用来出图的基础形象。
2. **决定要不要看幕后。** 预览和折叠标题使用无剧透的描述。作者主动点「查看幕后设定」才看见具体内容。作者在编辑区看过秘密，玩家侧仍按剧情里的揭晓时机呈现。
3. **修正理解。** 可以直接改一项，也可以说「保留这个世界，让两位主角开场就是旧识」。AI 与作者设定冲突时沿用作者设定。两条作者设定确实互相矛盾时，并列呈现冲突的原话及受影响的体验，让作者就地调整。例如，要求显示完整人物身份又要求身份保密时，可以先显示玩家已知称呼，揭晓后再更新。
4. **确认方向。** 一次点击「确认方案，生成开场」即可。方案尚未生成就中断时，回到已填写的背景和设置；确认方案后生成开场失败时，保留已确认的方案，作者可直接重试。

**录入人物参考。** 「人物参考」里放正面、斜侧脸和全身三个位置。作者可逐张选择本机图片，也可按形象文字生成正面，再以它为依据点「补齐视角」。生成前可展开「生成设置」，从该服务支持的档位里选择比例和分辨率，初次打开用适合人物参考的默认构图。导入时可先预览构图，会提示每个位置最好能看清哪些特征。图片格式或大小不合适时，说明原因并保留已录入的图。图片在本机保存，录入无需配置出图服务。主动生成时，界面会说明所选图片将发给哪个服务。

有一张满意的正面图就能点「采用这组」。其余视角可以之后再补，关掉页面也能继续编辑。逐张替换、重画和失败重试先留在正在编辑的参考组里。换正面时，界面把旧的斜侧脸和全身标成待复核，作者确认仍是同一个人后才能一起采用。卡片区分「当前使用」和「正在编辑」。采用或撤下参考组时，界面说明之后的新开局会用到什么，以及已有开局仍可用原图出图。作者随时可以确认故事方案。

## 4. 用玩家视角预览、修改并采用开场

先看作品标题和无剧透简介，再从玩家点击「开始故事」的位置预览。如果作者给主角留了填写项，可以试填一次；接下来看到整段正文、初始状态、推荐行动和自由输入。开场应让玩家理解自己的处境，并停在一个由玩家决定的时刻。

| 想改什么 | 操作 | 怎样确认改对了 |
| --- | --- | --- |
| 一句旁白、对白或具体设定 | 直接点中编辑，可撤销 | 就地试读新句，检查说话人、称呼和语气。 |
| 会影响多处的设定 | 用自然语言告诉 AI 想改什么 | 预览受影响的关系、正文、状态和选项。作者可接着手改、采用或放弃这次建议，先前的手改保留。 |
| 开场 | 比较候选，采用其中一个 | 新开局都从同一个时间、地点和处境起步。每局生成人物时可预览不同人物怎样进入这个开场。选用作者原文时保留其措辞；主角姓名留给玩家填写时，作者可以在原文里插入「主角名」占位符，开局时换成玩家填写的名字。若原文写死的人物或主角姓名与开局设置冲突，预览标出具体句子，作者可以换成占位符或通用称呼，或调整对应设置。 |

作者采用的开场和初始状态应互相吻合。比如把两个人从陌生人改成旧识，第一组选项和关系栏都应体现变化。若采用开场后又修改了影响开局的设定，回到草稿时指出受影响的正文、状态或选项，保留作者写过的内容供核对。采用一致的预览后，可直接保存或进入试玩。

## 5. 试玩，把值得留下的内容带回作品

试玩页标明「作者试玩」，可以使用正式游玩的全部操作：整段阅读、连续滚动、推荐行动、自由输入、状态栏、手记、手动存档、从存档另开和「换一种发展」。点「返回创作」回到刚才的草稿。每次从开场重新试玩都使用当前草稿和新的试玩进度。试玩时的主角试填值、建立的关系、作出的选择和发现的秘密只属于那次经历。

试玩和正式开局都可选插图或纯文字，遵守[游玩流程 §2.1](./gameplay-flow.md#21-插图)。正式开局按发布版本的人物形象匹配已采用的参考组，试玩按试玩快照匹配。新开局会固定当时选定的参考组。试玩时可以走一段人物换装或互动的剧情，检查是否还能认出同一个人，以及谁在行动、谁在回应。

作者可以用三次操作检查一部作品：试一个推荐项，看角色是否符合设定；输入一个未列出的行动，看 AI 能否接住意图并把重要决定留给玩家；在另一幕再次涉及此前行动，核对它是否产生应有的后果。想验证条件场面时，可用手动存档分别试玩满足条件与未满足条件的路线。

**从试玩加入作品设定。** 遇到喜欢的人物或对白时，直接选中并点「加入作品设定」。预览中可以单独选择身份、说话习惯或一句原话，修改后加入创作草稿。例如可以留下一个修表师的口头禅，把「他替这位玩家修过表」留在该次试玩中。若希望所有玩家与他都是旧识，作者可明确写成初始关系。保存作品后，新开局便可用到这些设定。

## 6. 存入作品库和日后改稿

首次存为可玩作品时，确认标题、玩家可读简介和已采用的开场。作者只写过背景时，标题与简介由 AI 先拟，作者可直接采用。成功后显示「开始故事」和「返回作品库」。作者本人点击开始，也会得到独立的正式进度。保存失败时保留草稿和重试入口。之后标题和简介随时可以在创作页修改，保存后作品库和已有的路线都立即显示新的。

**改稿规则：修改用于之后的新开局。** 编辑过的作品点「应用到新开局」时，界面说明哪些经历会受影响。标题和简介不受这条规则约束：它们只用来辨认作品，不影响任何路线里的故事。现有路线继续原有设定，从旧手动存档另开也沿用该时点的世界。这样作者可以收紧一个期限或重写关键人物，同时让已经开始的玩家顺利走完。

## 7. 验收

| 从什么情况开始 | 操作 | 可观察的通过结果 |
| --- | --- | --- |
| 本机作品库为空 | 只写一句背景，确认方案、采用开场、保存 | 得到可玩的作品，没有被要求补齐人物表或准备图片。 |
| 方案里有两位固定人物，手边有一张正面图 | 为一位导入正面图并采用，另一位留空，确认方案并试玩。回草稿替换参考组，再次试玩 | 录入不需要出图服务。方案照常确认。开启插图时，新试玩用新采用的参考，第一次试玩沿用自己的参考。 |
| 背景是唯一输入，或生成在中途中断 | 分别从生成方案前、确认方案后重试 | 前者保留背景和默认设置；后者沿用已确认方案生成开场。两次都能走到可玩的作品。 |
| 方案已生成 | 改一项设定，退出并回来 | 继续编辑到原处，生成开场前仍有确认方案的机会。 |
| 同一作品试两种角色模式 | 各看两次全新开局，再从一个旧存档分线 | 新开局都从作者采用的同一个开场起步：固定人物时复用作者采用的开场，只把主角填写项的占位符换成这次填写的值；每局生成人物时按同一处境重写，人物可以不同；分线保留存档时的角色。 |
| 作者设计了秘密与解锁条件 | 分别在幕后折叠和展开时试玩家预览 | 简介、称呼、状态栏、选项及手记都只透露本路线应知的信息。 |
| 主角姓名留给玩家填写，开场使用作者原文 | 用一个试填姓名预览，再由正式玩家填另一个名字 | 「主角名」占位符换成这次填写的姓名，其余措辞保持作者原文；写死的姓名在预览时被标出；正式游玩中的称呼遵循玩家这次填写的姓名。 |
| 试玩中临时出现新人物 | 只选身份和原话加入草稿，存为作品再新开局 | 新人物可在作品中出现，试玩经历仍独立；旧路线也能继续。 |
| 两部题材不同的作品均有进度 | 分别编辑、试玩、继续正式路线 | 每个入口都有清楚的作品归属，背景、状态和人物经历互不混入。 |

作品版本的技术设计见[数据模型](./data-model.md)，工作站和提案卡见[创作工作站](./author-workstation.md)，其余见[架构总览的文档索引](./architecture.md#文档索引)。
