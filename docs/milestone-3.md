# Unwritten 第三个里程碑：桌面窗口与作者设定

**目标：** 沿着[第二个里程碑](./milestone-2.md)的路径，做两件事。

- **装进桌面窗口。** desktop 启动并看护 core，在一个安全的窗口里打开 client。从访达或 Dock 启动时读到登录 shell 的环境变量，原生菜单和标题栏跟随外观偏好，⌘+、⌘-、⌘0 缩放版式。core 起不来或意外退出时，desktop 说明原因并提供重试。能打出一个在本机运行的安装包。
- **作者能写设定，游玩能用上设定。** 背景之外，作者可以补充世界、主角、主要人物、秘密、开场、行动提示、关键场面与结局、初始状态栏。AI 先生成故事方案，作者看过、改过、确认后再生成开场。游玩时，状态栏、秘密、关键场面、结束条件、行动提醒、主角填写项和每局生成人物都接进回合循环。

交付方式：维护者在本机运行 desktop 的开发模式或打出的包。core 独立运行、用浏览器打开的方式照常可用，两种方式的行为一致（[架构总览 §9](./architecture.md#9-验收)）。

## 作者和玩家能做什么

| 环节 | 可交付的体验 |
| --- | --- |
| 打开应用 | 双击应用或从 Dock 启动，只开一个窗口；再次启动时聚焦已有窗口。窗口只显示 client，外部链接交给系统浏览器。原生菜单、标题栏跟随外观偏好；⌘+、⌘-、⌘0 缩放，菜单里没有原地刷新。 |
| 启动失败与恢复 | 数据目录被占用、迁移失败或 core 没有按时就绪时，desktop 说明原因、给出诊断编号，提供「重试」和「退出」。游玩中 core 意外退出时，提供「重启」；重启后已保存的进度完整，生成到一半的那一段显示为未完成，可以重试。 |
| 环境变量里的 key | 端点的 key 写成 `$VAR` 时，从 Dock 启动也能读到 `~/.zshrc` 里的变量。 |
| 补充设定 | 首屏仍然只要求背景。展开「补充设定」后，可以按节填写世界、主角、主要人物、秘密与知情、开场、行动与提示、关键场面与结局、初始状态栏；每节都能留空。主要人物整部作品选「固定主要角色」或「每次新开局生成」，行动提示选「只显示行动」或「提醒已知后果」，默认分别是前者。 |
| 故事方案 | 点「生成故事方案」后看到玩家身份、主要人物或人物位置、基调和开场处境，每项标出来自作者还是 AI。秘密、幕后事件默认折叠，点「查看幕后设定」才展开。作者可以直接改一项；AI 发现两条作者设定矛盾时，并列显示两段原话。点「确认方案，生成开场」一次即可。 |
| 开场 | 开场可以让 AI 起草、按作者写的情境写，或采用作者原文。作者原文里可以插入主角填写项的占位符。原文写死了本该留给玩家填写的名字时，预览标出这些句子，不能采用。 |
| 开始故事 | 作者给主角留了填写项时，玩家开局先填这些；留空的用作者给的默认值。固定人物的作品直接读到作者采用的开场；每局生成人物的作品，开局时先生成本局人物，再写开场。开场失败时可以「重试这次开局」或返回作品库。可玩作品可以「重新开局」。 |
| 状态栏 | 最新段落下方显示作者设定或 AI 新增的栏目：数字带单位和进度条，阶段只写已到达的阶段名，清单逐项标状态。本回合变了的栏目标出变化。点开栏目看到来历，并能跳回原文。幕后栏目永远不显示，事情了结的栏目收进「已了结」。 |
| 秘密与关键场面 | 秘密只在主角得知时进入手记；游玩中 AI 也能创造秘密。满足作者写的条件时，AI 安排关键场面，「只发生一次」的场面在一条路线上只发生一次。 |
| 行动提醒与结局 | 选了「提醒已知后果」的作品，推荐行动下方附一行只用主角已知信息写的提醒。写了结束条件的作品，路线可以完结；完结后不再显示行动输入，提供「重新开局」。 |

## 实现顺序与检查点

1. **进程消息通道。** contracts 新增 `/desktop` 入口，定义启动、就绪、外观变化、日志、停止几类消息。core 在 utilityProcess 里从消息通道读启动参数，独立运行时照旧读命令行。[架构总览 §2.3](./architecture.md#23-core-与-desktop-的进程消息通道)
2. **desktop 外壳。** 单实例、启动和看护 core、窗口安全设置、原生菜单、外观同步、登录 shell 环境变量、启动错误与重启。desktop 的运行事件经消息通道写进诊断库。[架构总览 §2](./architecture.md#2-进程模型) · [运行诊断 §1](./diagnostics.md#1-存储与生命周期)
3. **本机安装包。** electron-builder 打出未签名的包，core 的构建产物和运行依赖、client 的构建产物放进资源目录，用 fuses 关闭不需要的 Electron 能力。[技术选型 §4](./tech-stack.md#4-desktop)
4. **补充设定与故事方案。** 草稿保存各节补充设定；`plan` 生成任务用 `author_chat` 用途产出方案，确认方案时把人物、秘密、状态栏定义写进草稿的故事事实，把关键场面、结束条件、主角填写项和人物位置写进草稿。[创作流程 §2–3](./authoring-flow.md#2-写背景只补自己在意的设置) · [创作工作站 §9](./author-workstation.md#9-生成任务) · [数据模型 §2](./data-model.md#2-作品与版本)
5. **开场与开局。** 预览按方案和开场方式生成，采用时只发布、不建开局。开局由玩家发起，固定人物直接替换占位符，每局生成人物先生成人物再写开场。[回合循环 §10](./turn-loop.md#10-开场)
6. **回合循环接上设定。** `changes` 开放 `state`、`state_item`、`new_state`、`secret`、`scene_hit`；上下文加入在场者相关的秘密、状态栏、未触发的关键场面和结束条件；推荐行动可以带提醒；按结束条件允许完结。[回合循环 §3](./turn-loop.md#3-上下文哪些直接给哪些让模型查) · [回合循环 §5–6](./turn-loop.md#5-提交一回合propose_turn-与-ask_clarification) · [数据模型 §4–5](./data-model.md#4-故事事实)
7. **界面。** 创作页按步骤排出背景、方案、开场；开局页收集主角填写项；游玩页加状态栏、行动提醒和完结状态；设置页列出 `author_chat` 用途。[a11y §9](./a11y.md#9-创作页与工作站)
8. **端到端。** 浏览器模式覆盖作者设定到游玩的全程，Electron 模式覆盖启动、外观同步、core 意外退出后重启。

1–3 在 desktop、contracts 和 core 的入口，4–7 在 core、contracts 和 client。两条线只在 contracts 的不同文件上相交，可以并行。

## 留给后续的能力

| 能力 | 推迟的理由 |
| --- | --- |
| 签名、macOS 公证、自动更新、发布流程，以及 Windows 和 Linux 的安装包 | 维护者决定本次只要本机能用的包。未签名的应用在 macOS 上无法使用自动更新，自动更新随签名一起做 |
| 创作工作站：对话面板、提案卡、用自然语言修改设定 | 向导按钮已经覆盖最短路径。修正方案时，作者直接改那一项 |
| 方案的逐项对比视图 | 生成期间作者改过草稿时，先给出「仍然采用」和「重新生成」两个选择 |
| 试玩与「加入作品设定」 | 依赖工作站的 `trial_extract` 卡片 |
| 换一种发展、手动存档、从存档另开、所有路线列表 | 状态栏和秘密的可见性已按回合树设计，分线时不用改 |
| 采用开场后再改稿、「应用到新开局」 | 改稿规则要说明对已有路线的影响，界面和发布流程另做 |
| 开场的就地编辑、候选比较 | 依赖工作站和 `opening_candidates` |
| `ask_clarification`、尚未发送的输入草稿 | 同第二个里程碑 |

## 验收

| 从什么情况开始 | 操作 | 应当看到的结果 |
| --- | --- | --- |
| 应用已打开 | 再启动一次应用 | 没有第二个窗口，已有窗口被聚焦 |
| 外观偏好为浅色，系统为深色 | 在设置里改为深色，再改为跟随系统 | 原生标题栏和菜单随之变化；`nativeTheme.themeSource` 先后为 `dark`、`system` |
| 另一个 core 正占用数据目录 | 启动应用 | 对话框说明数据目录被占用，带诊断编号；点「重试」在占用解除后进入作品库 |
| 游玩中正在生成 | 强制结束 core 进程 | 对话框提供「重启」；重启后路线完整，刚才的请求显示为未完成，可以重试 |
| `providers.json` 里的 key 写成 `$VAR`，变量只在 `~/.zshrc` 里 | 从 Dock 启动应用，测试连接 | 连接成功，设置页显示 key 来自该环境变量 |
| 打出的本机安装包 | 安装后启动，走一遍创作和游玩 | 和开发模式行为一致；`RunAsNode` 已关闭，用 `ELECTRON_RUN_AS_NODE=1` 启动不能当 Node 用 |
| 只写一句背景 | 生成方案、确认、生成开场、采用、开始故事 | 方案里标出 AI 补全的项；一路点完得到可玩的作品 |
| 作者写了一个秘密，设了一个范围 0 到 10 的数字栏目和一个「只发生一次」的关键场面 | 确认方案后开局，玩几回合 | 方案里秘密默认折叠；状态栏显示数字和进度条；秘密在主角得知前不进手记；关键场面在本路线只触发一次 |
| 主角姓名留给玩家填写，开场用作者原文并插入占位符 | 采用开场，玩家填一个名字开局 | 开场正文和第一组选项显示玩家填的名字；原文写死主角名时预览标出那句并拒绝采用 |
| 主要人物设为每次新开局生成 | 开两局 | 两局都从同一处境起步，人物可以不同；第一局开场失败后重试，沿用已生成的人物 |
| 作品写了结束条件 | 玩到满足条件 | 最后一段标为完结，行动输入消失，提供「重新开局」；没写结束条件的作品，模型交上 `ending: "true"` 被拒绝 |
| core 独立运行 | 用浏览器走一遍上面的创作与游玩 | 和桌面窗口的行为一致，client 代码里搜不到桌面专属分支 |
