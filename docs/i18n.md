# Unwritten · 国际化（i18n）

本文定义界面文案怎样管理、core 返回什么、作品语言与界面语言的关系，以及中文排版和输入法的处理。

## 1. 范围

**i18n 只管界面文案**，包括按钮、菜单、提示、空态、错误、通知、文档标题，以及 `aria-label`、`placeholder`、`title`、`alt` 这些属性。

**数据永远原样显示，不翻译**，包括：

- 作品标题与正文；
- 作者设定；
- AI 生成的剧情、选项和回复；
- 玩家的输入；
- 端点名和模型 id；
- 插图的画面说明、出图服务报告的实现名和模型名。

## 2. 语言

- 界面只有简体中文（`zh-CN`）。
- **文案从第一行代码起就走 i18n 层。** 理由有三：
  - 写死在组件里的文字，以后很难完整找出来；
  - 所有文案集中在一处，便于统一审校语气；
  - 读屏用到的名称和界面上的文字来自同一处，不会出现两种说法。
- **伪语言 `pseudo`** 只在开发版本里提供，构建时由 `zh-CN` 自动生成：每条文案前后加上 `⟦` `⟧`，并拉长约四成。切到伪语言后：
  - 应翻译的界面文案没有括号，说明它绕过了 i18n；
  - 被截断或撑破布局的地方，说明容器没有给文字留余量。

## 3. 方案与文件

- **库：** i18next + react-i18next，React 生态里使用最广的 i18n 方案。
- **文件位置：** `apps/client/src/i18n/zh-CN/<命名空间>.json`。
- **命名空间按功能划分：** `common`、`library`、`authoring`、`workstation`、`play`、`settings`、`errors`。`common` 和 `errors` 随首屏加载，其余随路由按需加载。
- **键名**的格式是 `<命名空间>:<区域>.<元素>[.<状态>]`，例如 `play:action.submit`、`play:action.submitting`。
  - 键名表达用途，不复述文字；
  - 中文字面相同但用途不同的文案，用不同的键。例如“保存”存草稿和“保存”存档是两个键，因为将来翻译时它们可能是不同的词。
- 根元素的 `lang` 属性等于界面语言。
- **desktop 的文案。** desktop 不是 web 页面，没有 i18next。原生菜单、启动错误和意外退出对话框的文字放在 `apps/desktop/src/i18n/zh-CN.json`，键名写成 `desktop:<区域>.<元素>`，由 desktop 自己的 `t()` 读取，插值、标点和语气同 §4。菜单项都显式写文字，不用 Electron 按菜单角色给出的英文默认文字。

## 4. 文案规则

- **组件里不出现用户能看到的字面字符串**，属性里的也算。
- **不拼接字符串来组句**，一律用插值：`t('play:save.done', { name })`。带链接或加粗的句子用 `<Trans>` 组件。不同语言的语序不同，拼接出来的句子换一种语言就碎了。
- **数量统一用 i18next 的 `count` 写法。** 中文没有单复数变化，但这样写，将来加语言时代码不用改。
- **文案的语气**按[设计准则 §8](./design-guidelines.md#8-文案语气)。
- **标点：**
  - 用全角中文标点；
  - 引用界面元素的名字用「」，例如：点「开始故事」；
  - 引用一句话用“”。
- **中文和数字、英文之间不手动加空格**，由 CSS 自动加间距（§7）。这样所有文案的间距保持一致。

## 5. core 返回什么

- **core 不返回给用户看的文字。** 错误码的唯一清单在 contracts 的 `errors.ts`，`errors:<code>` 的键和它一一对应。错误采用 `code`、`message`、`data.detail` 和可选的 `data.diagnosticId`：
  - `message` 只供开发者阅读，不显示在界面上；
  - client 按 `code` 查 `errors:<code>` 显示对应文案；
  - 查不到的 `code` 显示 `errors:unknown`，并附上这个 `code`，方便排查；
  - 有诊断编号时，错误提示显示可选中的编号。后台生成失败用原任务或请求编号。查询方式见[运行诊断与性能记录 §2.1](./diagnostics.md#21-错误提示与诊断编号)。
- **client 区分本机连接与模型连接。** 本机 HTTP 连接失败提示确认应用仍在运行，令牌失效打开原有的无令牌说明页，模型服务的连接失败提示检查端点。
- **desktop 的启动失败也只给原因代码。** core 经 `start-failed` 消息给出原因（`data_locked`、`port_in_use`、`data_dir`、`startup`）和诊断编号，desktop 按原因查 `desktop:startup.reason.<原因>` 显示；就绪超时和启动中退出是 desktop 自己判断的两种原因，同样查表。
- **状态和事件也只返回代码与参数**，例如请求状态 `needs_clarification`、失败原因 `context_too_small`，由 client 翻成文案。
- **模型服务返回的原始错误信息**属于数据，由 core 去掉凭据后放在“详细信息”里显示，不翻译，也不冒充成我们自己的文案。

## 6. 作品语言

- 每部作品有自己的语言，存在 `meta.narration.language`（[数据模型 §2](./data-model.md#2-作品与版本)）。生成故事方案时，按作者背景所用的语言定下；认不出时用 `zh-CN`。作者可以在补充设定的“叙事与开场”里修改。
- narrator 用作品语言写剧情和选项，和界面语言无关。
- 工作站的 AI 用作者在对话里使用的语言回复。
- 正文区域的 `lang` 属性等于作品语言，读屏软件据此选择发音，浏览器也据此选择字体和断行规则。
- core 里给模型的提示词是内部实现，不属于界面文案，不走 i18n。
- **发给出图服务的提示词一律用英文，** 各家出图模型对英文最稳；插图的画面说明给玩家看，用作品语言写（[插图与出图服务 §8](./image.md#8-镜头描述)）。画风预设的名字是界面文案，走 i18n；它对应的提示词片段是英文常量，不走 i18n。

## 7. 中文排版

- **标点禁则。** 正文和界面文字都设 `line-break: strict`，句号、逗号不出现在行首。
- **中西文间距和标点挤压。** 在 `@supports` 守卫下启用 `text-autospace: normal` 和 `text-spacing-trim: normal`：中文与英文、数字之间自动留出间距，相邻的标点自动挤压。浏览器不支持时不额外补空格，也不挤压标点，按普通断行显示。
- **不用斜体。** 中文没有真正的斜体，正文里的 `em` 改用字重表示强调。
- **长串不撑破布局。** 端点地址、模型 id 这类不断行的长串，设 `overflow-wrap: anywhere`。
- **不给中文正文加字距。** 字距 token 只用于标题（[主题与 token §4.1](./theme.md#41-排版)）。
- **输入法：**
  - 自由输入框和工作站输入框里，Enter 发送，Shift+Enter 换行；
  - 输入法正在组字时（`compositionstart` 到 `compositionend` 之间，或者事件的 `isComposing` 为 true），Enter 只用于确认组字，不发送。不处理这一点的话，中文用户按回车选字时，消息会被误发出去。

## 8. 布局方向

- **一律使用逻辑属性：**
  - 用 `margin-inline-start`，不用 `margin-left`；
  - 用 `inset-block-end`，不用 `bottom`；
  - 用 `inline-size`，不用 `width`；
  - `text-align` 用 `start` 和 `end`，不用 `left` 和 `right`。
- 现在只有从左到右的横排，但这样写以后支持从右到左的语言，或者竖排正文时，不需要重写样式。
- 带方向含义的图标（返回、前进箭头）只在一个共享组件里处理，将来按 `:dir()` 翻转。

## 9. 格式化

- **真实世界的日期、数字、相对时间**用 `Intl.DateTimeFormat`、`Intl.NumberFormat`、`Intl.RelativeTimeFormat` 按界面语言格式化，例如作品卡上的“3 小时前”。不引入 moment 一类的库。
- **故事里的时间**（例如“深夜”“第三天”）是 AI 写出的数据，原样显示。
- **快捷键**按平台显示：macOS 显示 ⌘，其他平台显示 Ctrl。由一个共享函数生成，按键名称走 i18n。

## 10. 强制检查

- **oxlint：** 通过 oxlint 的 JS 插件加载 `eslint-plugin-i18next`，用它的 `no-literal-string` 规则拦下 JSX 文本，以及 `aria-label`、`placeholder`、`title`、`alt` 里的字面字符串。
- **文案键测试：**
  - 代码里用到的每个键，在 `zh-CN` 里都存在；
  - `zh-CN` 里没有任何地方使用的键，列出来提醒删除。
- **伪语言：** 开发版本的设置里可以切换到伪语言，配合 §2 的用法检查。

## 11. 不做的事

- **简体中文以外的界面语言。** 结构已经就绪，加语言只需要增加语言包。
- **翻译用户内容**，包括正文、设定和输入。
- **简繁自动转换。**

## 12. 验收

| 从什么情况开始 | 操作 | 应当看到的结果 |
| --- | --- | --- |
| 开发版本 | 切换到伪语言，走一遍作品库、创作、游玩、设置 | 界面文案带 `⟦…⟧`，作品内容、输入和模型 id 原样显示；没有被截断或撑破布局的地方 |
| 在组件里写一个中文字面量或写死的 `aria-label` | 运行 oxlint | 报错 |
| 自由输入框 | 用拼音输入法打字，按 Enter 选字 | 只确认组字，消息没有发出；再按一次 Enter 才发送 |
| core 返回一个 client 不认识的错误码 | 触发这个错误 | 显示通用的错误文案，并附上这个错误码 |
| 正文里有中英混排和连续标点 | 查看游玩页 | 中英文之间有间距，标点不出现在行首 |
