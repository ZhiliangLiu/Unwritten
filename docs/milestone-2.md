# Unwritten 第二个里程碑：记得住的故事，读得舒服的界面

**目标：** 沿着[第一个里程碑](./milestone-1.md)的路径，做三件事。

- **故事记得住发生过的事。** 每个回合把新出场的人物和地点、称呼、事件、特征、关系、约定，以及谁知道什么，写进作品库。续写时，core 把当前场景、在场者和索引直接放进 prompt（推送），其余细节由模型用只读工具自己查（拉取）。很多回合以后，旧人物、旧约定仍能接回来，角色只依据自己目击或听说过的事行动。
- **界面做成设计文档描述的样子。** 补齐共享部件，按 Figma 校准过的稿子重做作品库、创作、游玩、设置四页，加上外观与阅读偏好和手记。
- **每个用途单独配置模型和生成参数。** 包括思考档位与预算、`temperature`、`top_p`、`top_k`、`min_p`。

交付方式同第一个里程碑：维护者用浏览器打开独立运行的 core 所提供的 client。[架构总览 §2.2](./architecture.md#22-core-独立运行)

## 作者和玩家能做什么

| 环节 | 可交付的体验 |
| --- | --- |
| 配置模型 | 设置页为游玩（`narrator`）、后台摘要（`background`）和默认三个用途分别选择模型，并为每个用途设置生成参数。没填的参数不发送，由服务端决定。可以用某个用途的实际模型和参数测试连接。 |
| 外观与阅读 | 设置页切换跟随系统、浅色、深色，调节正文字号、字体和行距。偏好存在 core，刷新和换标签页后保持，首屏不闪。 |
| 作品库 | 页头有标志。作品排成卡片网格，卡片上只有标题、简介、状态徽标和一个主入口。空库时直接引导新建故事。 |
| 写背景和预览开场 | 背景编辑区有起笔提示，自动保存并标出保存状态。预览按玩家看到的版式排出开场，并列出开场里出场的人物和地点。改过背景后，旧预览标为过期。采用后给出「开始故事」和「返回作品库」。 |
| 游玩 | 单列正文，像书页。玩家行动用强调色的界面字夹在两段剧情之间。推荐行动一行一个、带序号，按 ⌘1–⌘9 可选。新段落整块淡入，生成中有呼吸标记。往上翻阅时新段落到达，阅读位置不动，出现「回到最新」。失败时在原位置重试。输入框已有文字时点推荐行动，先问玩家用哪一个。 |
| 手记 | 从游玩页工具行打开，从右侧滑出，盖在正文之上。按人物、地点、事件分组，只列主角知道的内容，人物按主角知道的称呼显示。点出处跳回原文并短暂高亮，关闭后阅读位置不变。 |
| 连贯 | 早先出场的人物、称呼、交出的物品和答应的约定，在很多回合以后仍被接住。没在场的角色不会知道当时发生的事。正文和选项不出现主角还不知道的名字。 |

故事事实这次只做人物关系这条主干。它不依赖作者额外写设定，只写一句背景的作品也能用上。状态栏、秘密和关键场面都需要作者先写设定，留给作者设定向导一起做。

## 实现顺序与检查点

1. **按用途配置模型与生成参数。** 用途分配带上生成参数，`llm.purposes.get` 和 `llm.purposes.set` 一并读写参数，`llm` 模块调用时按用途换算成 pi-ai 的选项。测试连接可以按用途发起。设置页隐藏 `author_chat`，因为目前没有调用方。[LLM 端点 §7](./llm-endpoints.md#7-用途分配) · [LLM 端点 §10](./llm-endpoints.md#10-core-接口)
2. **开场写入初始事实。** 预览工具的输出增加 `changes`：主角、开场里出场的人物和地点、初始场景。采用时随开场存进发布版本。提交根回合时，在同一事务里写入这些事实。迁移为已有的发布版本补一个主角实体，旧路线的其余事实从下一个回合开始积累。[数据模型 §4](./data-model.md#4-故事事实) · [回合循环 §10](./turn-loop.md#10-开场)
3. **回合写入事实。** `propose_turn` 的 `changes` 开放 `new_entity`、`name`、`event`、`trait`、`relation`、`promise`、`knowledge`、`scene` 八种类型。工具说明里不列其余类型，模型交上来时按未知类型返回修正。引用、新人物去重、知情和不泄露按回合循环的规则校验。事件目击者展开成知情记录，与回合在同一事务里提交。[回合循环 §5–6](./turn-loop.md#5-提交一回合propose_turn-与-ask_clarification) · [数据模型 §5](./data-model.md#5-可见性规则)
4. **推送与拉取。** 按预算组装上下文：叙述约定、作品硬设定、行动原话、当前场景和在场者、实体索引和未了结的约定、最近的回合原文、更早回合的摘要行。人物、事实、回合用短编号表示。提供七个只读工具，每回合最多 8 轮工具调用，足迹写进 `turn_requests.log`。秘密、状态栏和关键场面这几行材料暂时没有来源，先不放进上下文。[回合循环 §3–4](./turn-loop.md#3-上下文哪些直接给哪些让模型查)
5. **后台摘要和全文索引。** 回合提交后用 `background` 用途排队写摘要，失败时退回“回合编号 + 玩家行动”。全文索引在提交事务里写入。core 启动时为缺摘要的回合补排，迁移为已有回合补建全文索引。[回合循环 §9](./turn-loop.md#9-后台摘要) · [数据模型 §6](./data-model.md#6-派生数据)
6. **Figma 校准。** 在 Prototype 页把作品库、创作、游玩、手记、设置和深色稿对齐到设计文档，维护者确认后再写界面代码。稿子和文档冲突时，先改文档。
7. **共享部件。** 用 Base UI 和 Lucide 做出设计准则 §9 列出的部件，以及页面工具行、对话框、通知和骨架屏。每个部件都跑 axe-core 检查，页面不再各自拼样式。[设计准则 §9](./design-guidelines.md#9-部件) · [client 编码规范](../apps/client/AGENTS.md)
8. **页面、手记和外观偏好。** 用共享部件重做四页，按动效文档的场景编排加上过渡。路由切换时更新标题并移动焦点。手记走主角视角投影。外观偏好通过 `settings.get` 和 `settings.update` 存进 core，返回 `index.html` 时写在根元素上。[设计准则 §4](./design-guidelines.md#4-布局) · [动效 §5](./motion.md#5-场景编排) · [主题与 token §9](./theme.md#9-外观偏好与切换) · [可访问性 §8](./a11y.md#8-游玩页)

1–5 在 core 和 contracts，6–8 在 client。第 6 步可以和 1–5 并行。

## 留给后续的能力

| 能力 | 推迟的理由 |
| --- | --- |
| 状态栏、秘密、关键场面 | 这三样都要作者先写设定才有意义，和作者设定向导一起做。表结构和 `changes` 类型按现有设计扩展，不改动已经写下的事实。 |
| `ask_clarification` | 澄清要另做一套请求状态和界面。M2 先验证模型能否靠推送和拉取接住自由行动。 |
| 作者设定向导、创作工作站、试玩 | 一句背景加开场预览已经能产出带初始事实的作品。 |
| 换一种发展、手动存档、从存档另开、重新开局 | 一条路线足以验证事实的写入和可见性。可见性规则已按回合树设计，分线时不用改。 |
| 尚未发送的输入草稿 | 要新增接口和存储，并处理多页面并发写入。M2 专注于视觉和交互。 |
| 自定义透传参数、最大输出和上下文窗口的按用途配置 | 已选的六项参数覆盖了常用场景。上下文窗口和输出上限仍是模型元数据。 |
| `author_chat` 用途 | 目前没有调用方。 |
| Electron、安装包、自动更新 | 同第一个里程碑。 |

## 验收

| 从什么情况开始 | 操作 | 应当看到的结果 |
| --- | --- | --- |
| 已配置一个支持思考的模型 | 给 `narrator` 设为 `high` 并填 `temperature`、`top_k`，给 `background` 设为 `off`，各自测试连接，再玩一个回合 | 伪服务商收到的续写请求带上对应字段，摘要请求不带思考字段，没填的参数都不出现。能力为“否”的模型不能选思考档位。 |
| 同上，模型的思考写法分别设为 `qwen` 和 `openai` | 给 `narrator` 设档位和思考预算，各发一次续写；再把档位设为关闭 | `qwen` 写法的请求带 `enable_thinking` 和 `thinking_budget`；`openai` 写法带 `reasoning_effort`，不带预算。档位为关闭时，`qwen` 写法发 `enable_thinking: false`，`openai` 写法发 `reasoning_effort: "none"`。没设档位的用途不带任何思考字段。 |
| 第一个里程碑留下的数据目录 | 启动新版 core，打开旧作品续玩一回合，再搜索旧回合里的一个词 | 迁移成功，旧路线可续玩，新回合开始积累事实，旧回合能被搜到。 |
| 默认模型已通过测试 | 写一句背景，生成并采用开场 | 预览列出开场里的人物和地点。开局后作品库里有主角和这些实体，手记能列出主角知道的部分。 |
| 开场已保存 | 第 2 回合结识一个人物并把一件物品交给他。用上下文窗口很小的伪服务商把最近原文挤出预算，继续玩到第 8 回合再提起那件物品 | prompt 里那个人物以短编号出现在索引中。模型用 `get_character` 或 `search_story` 取回旧事，`turn_requests.log` 记下足迹，新回应接得上物品的去向。 |
| 场上有两个人物，其中一人离场 | 留下的人物对主角说一件事，之后离场的人物回来 | 离场人物没有这条知情记录，`who_knows` 不列他。手记只列主角知道的内容，称呼按主角知道的写。 |
| 伪服务商分别返回：引用没下发过的编号、正文出现主角不知道的名字、知情者不在场也没写来源、未开放的 `changes` 类型 | 提交一回合 | 每种错误都逐条返回给模型修正；修正 2 次仍不通过时以 `invalid_output` 失败，路线停在原处，没有写入任何事实。 |
| 后台摘要的模型不可用 | 连续玩三个回合，再重启 core | 游玩不受影响，摘要行退回“回合编号 + 玩家行动”。模型恢复后，重启时补排缺失的摘要。 |
| 两部作品都有进度 | 交替续玩，并检查各自的上下文和手记 | 实体、事实、摘要和搜索结果互不混入。 |
| 任意页面，浅色和深色 | 截图，转成灰度，并用色盲模拟查看 | 符合设计准则 §12；每页只有一个主要操作，状态都能靠图标或文字分辨。 |
| 游玩页，玩家已向上翻阅 | 新段落到达，再打开、关闭手记，从手记跳回一处原文 | 阅读位置保持不变，出现「回到最新」。跳回的段落短暂高亮。关闭手记后回到原来的位置。 |
| 生产构建 | 切到深色、调大字号后刷新，再开一个新标签页；用键盘走完主路径，在输入法组字时按 ⌘ 加数字键和回车 | 偏好保持，首屏不闪。焦点清楚，组字时不选推荐行动、不提交，生成完成和失败都有播报。 |

验收和第一个里程碑一样分两部分。浏览器端到端测试用伪服务商和临时数据目录，覆盖参数传递、事实写入与校验、可见性、迁移和界面状态。再用真实模型手动走一遍，看很多回合后旧人物和旧约定是否被自然接住，界面是否读得舒服。[技术选型 §8](./tech-stack.md#8-测试) · [可访问性 §11](./a11y.md#11-测试) · [设计准则 §12](./design-guidelines.md#12-验收)
