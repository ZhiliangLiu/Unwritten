# Unwritten · 设计准则

本文是所有界面设计决定的依据：做一个新页面、选一个颜色、加一段动效之前，先对照这里。具体的取值在[主题与 token](./theme.md)和[动效](./motion.md)里，文案与语言见 [i18n](./i18n.md)，可访问性见 [a11y](./a11y.md)。

## 1. 基调

**简约、高雅、护眼，适合长时间阅读。** Unwritten 的主角是故事正文，界面要像一本排得好的书，读者看的是内容，不是界面。

- **阅读优先。** 正文区像一页书：衬线字体、舒适的行距和版心宽度、柔和的纸色与墨色。界面控件退在一旁，字号更小，颜色更淡。
- **原生质感。** 界面贴近 macOS 原生应用：系统字体、跟随系统明暗、系统滚动条、平台习惯的快捷键。它不像网页后台，也不像游戏。
- **克制。** 每个元素都要有用途。宁可少一个装饰，也不要多一处干扰。

## 2. 七条准则

| 准则 | 怎么做 | 判断方法 |
| --- | --- | --- |
| **正文是主角** | 正文用衬线字体、独立的纸色和墨色；界面文字用无衬线字体，比正文小一到两档 | 把界面控件全部遮住，正文仍然读得舒服；把正文遮住，界面也不显得空洞抢眼 |
| **少即是多** | 一屏只有一个主要操作；次要操作收进菜单或降低视觉权重；不加装饰性图形、渐变和纹理 | 去掉某个元素，信息有没有损失？没有就去掉 |
| **安静的层次** | 用留白、字重、明度区分层次，少用边框和色块；分隔优先用间距，其次才用细线 | 截图转成灰度，层次依然清楚 |
| **护眼** | 不用纯白配纯黑；正文对纸面的对比度落在约 11:1 的舒适区间；深色不是浅色的反色，而是一套独立调过的低亮度配色；不闪烁，不大面积突然变亮 | 在暗室里读十分钟深色主题，眼睛不累；强光下读浅色主题，正文不发灰 |
| **克制的颜色** | 大面积只用带一点暖意的中性色；全应用只有一种强调色（墨蓝），只用于主操作、焦点、选中、玩家行动和刚变化的状态值；成功、警告、危险各有独立的颜色，并配图标或文字 | 一屏里强调色占的面积很小；色盲模拟下，状态仍然分得清 |
| **动效解释变化，不表演** | 按下立刻有反馈；出现和消失走同一条路；可以随时打断；默认不回弹；没有循环的装饰动画 | 关掉所有动效，界面依然完整可用；打开动效，没有哪一处让人等待 |
| **一致、可预期** | 长得一样的东西行为也一样；控件放在它影响的内容旁边；按钮写具体动作，例如“开始故事”，不写“确定” | 新用户不看说明，能猜到点下去会发生什么 |

## 3. 版式

- **两种字体。** 界面用系统无衬线字体（苹方 / system-ui），正文用衬线字体（宋体 / 思源宋体）。技术信息（端点地址、模型 id、快捷键）用系统等宽字体。不打包网络字体：作品库在本机，首屏不等字体加载。
- **正文排版。**
  - 默认字号比界面大，读者可以在阅读设置里调节；
  - 行距宽松；
  - 版心约 36 个汉字宽；
  - 段与段之间用段间距隔开，不首行缩进。这样对话多的段落更清爽。
- **玩家的行动**夹在两段剧情之间，用强调色和稍小的字号显示，与叙述明显区分开，但不加边框或色块。
- **标题**只用字重和字号区分，不加颜色、阴影或下划线。大号标题字距略收紧，正文字距为 0。
- **中文排版。** 遵守标点禁则（句号、逗号不出现在行首）；中文和西文之间留出间距；中文不用斜体，强调用字重。具体做法见 [i18n §7](./i18n.md#7-中文排版)。
- **尺寸**一律用 rem。系统或应用整体缩放时，版式跟着等比缩放。

## 4. 布局

- **游玩页：** 只有一列正文，居中。正文流的末尾依次是状态栏、推荐行动和自由输入。手记、存档等入口收在顶部的一行工具里，用时才展开。
- **创作页：** 主区是向导，右侧是可折叠的工作站面板。面板展开时主区让出宽度，不覆盖主区。
- **作品库：** 作品卡片网格，卡片上只有标题、简介、状态和一个主入口。
- **间距**以 4px 为基本单位。相关的东西靠近，不相关的东西拉开；同一组里的间距一致。
- **窄窗口：** 工作站面板变成从右侧滑出的浮层；正文列宽随窗口缩小，但字号不变。

## 5. 层次与材质

浅色和深色两套主题都只用不透明的表面，层次分三层：

| 层 | 是什么 | 怎样和下一层区分 |
| --- | --- | --- |
| 底 | 应用背景 | 无 |
| 表面 | 面板、卡片、正文纸、输入框 | 浅色：明度略高于底，加一条极淡的投影；深色：明度略高于底，顶边加一条极细的亮线 |
| 浮层 | 菜单、对话框、提示、通知 | 浅色：更深的投影；深色：再亮一档，加投影。对话框下面加一层半透明遮罩 |

- **深色靠明度分层，浅色靠投影分层。** 深色背景上投影几乎看不见，所以深色主题用“越高的层越亮”来表达抬起。
- **正文、卡片、输入框、通知永远不透明。** 读得清比好看更重要。通知虽然浮在上面，背景也不透明，因为它承载必须立刻读清的状态。
- **浮层从触发它的元素那里长出来**（见[动效 §5](./motion.md#5-场景编排)），关闭时回到原处。
- 界面的每个表面都通过“材质”token 取色，而不是直接取颜色。现在这些 token 都是不透明的；将来接半透明主题时，只需改 token 的值，组件不用动（见[主题与 token §6](./theme.md#6-材质预留给将来的主题)）。

## 6. 颜色

- **中性色带一点暖意。** 浅色像米白的书页，深色像夜里的暖灰，避免冷冰冰的纯灰。
- **强调色是墨蓝**，像钢笔墨水：浅色主题里偏深，深色主题里提亮、降低饱和度。强调色只用在：主按钮、焦点环、选中态、链接、玩家行动，以及刚刚发生变化的状态值（短暂高亮后淡回）。
- **反馈色**（成功、警告、危险、信息）都降低了饱和度，和整体的安静基调一致。它们只表示状态，不拿来装饰。
- 颜色不单独承载信息：状态一律同时有图标或文字。

## 7. 图标

- 全应用统一使用一套线性图标（Lucide），线宽一致，尺寸跟随相邻文字，有 16px 和 20px 两档。
- 主要操作用“图标 + 文字”；只有图标的按钮必须有可读的名称（见 [a11y §4](./a11y.md#4-键盘与焦点)），并且只用于含义一眼就能看懂的操作，例如关闭、更多。
- 不使用彩色图标、插画式图标或 emoji 充当界面元素。

## 8. 文案语气

- 简短、具体、平静。用动词开头写按钮。
- 不用感叹号，不卖萌，不用“亲”“哦”这类语气词。
- 错误提示写清两件事：发生了什么，怎么办。例如“连不上模型服务。请检查网络，或到设置里换一个端点。”
- 文案统一走 i18n，写法见 [i18n §4](./i18n.md#4-文案规则)。

## 9. 不做的事

- 渐变按钮、发光、霓虹、大面积彩色背景。浅色和深色主题里也不用半透明的玻璃效果；半透明只留给将来的专门主题，并受[主题与 token §6](./theme.md#6-材质预留给将来的主题)的约束。
- 拟物纹理：纸张纤维、皮革、木纹。“像书页”靠的是排版和配色，不靠贴图。
- 装饰性动画、视差、粒子、打字机效果。正文生成时直接追加文字，不逐字蹦出。
- 后台式的视觉：密集表格、到处是边框和分割线、满屏图标按钮。
- 同一页面出现两个或更多的强调色元素在争夺注意力。

## 10. 验收

| 从什么情况开始 | 操作 | 应当看到的结果 |
| --- | --- | --- |
| 游玩页，任意一部作品 | 浅色、深色主题下各连续阅读十分钟 | 正文舒适，不刺眼，不发灰；界面控件不抢视线 |
| 任意页面 | 截图转成灰度 | 层次仍然清楚：哪里是主操作、哪里是正文、哪里是浮层，一眼能分辨 |
| 任意页面 | 用色盲模拟（红绿、蓝黄）查看 | 每个状态都能靠图标或文字分辨 |
| 新页面设计稿 | 逐项对照 §2 的七条准则 | 每一条的“判断方法”都能通过 |
