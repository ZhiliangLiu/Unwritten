# 插图真实模型评测

这份文件固定真实模型和实机插图走查的输入、观察点和记录方法。设计依据见[插图与出图服务 §14](../docs/image.md#14-验收)和[任务 T30](../tasks/milestone-4.md#t30-端到端与评测)。浏览器自动化已经覆盖协议、尺寸、位置、失败和唤醒；这里只判断画面本身，不把关键词命中当作画质合格。

评测材料使用[附录 D.1](../tasks/milestone-4.md#d1-候船厅t12t19t29t31)的虚构故事《候船厅的纸灯》。真实提示词、正文、图片、授权页和地址只留在评测现场，不写进本文件或版本控制。

## 1. 固定条件

每次对照使用同一份正文、同一画风、同一档位和同一组引擎参数。

| 项       | 取值                                                                 |
| -------- | -------------------------------------------------------------------- |
| 作品     | 《候船厅的纸灯》，`zh-CN`                                            |
| 正文     | 附录 D.1 的同一回合五段，段落之间空一行                              |
| 画风     | `painterly`（厚涂）                                                  |
| 比例     | 自动比例                                                             |
| 档位     | 1K                                                                   |
| 参考组 A | 正面 + 全身                                                          |
| 参考组 B | 正面 + 全身 + 斜侧脸                                                 |
| seed     | 服务支持时固定，同一次 A/B 使用同一个 seed；服务不支持时记「不支持」 |
| 开局     | 固定人物、自动出图已确认、主角不入画                                 |
| 观察环境 | 维护者的 Mac，真实服务与本机 GPU；记录 GPU 与服务版本                |

参考组 A/B 只改参考位置，其余输入完全一致。换装、照明、线索和揭晓沿用同一对照，不另换画风或档位。

## 2. 五个场景

每个场景单独开局。截图、提示词和画面说明只作现场证据，评测记录只写编号、读数与判定。

### 2.1 多人交接钥匙

- **截取段落：** 第 2 段。
- **画面应出现：** 短发的修表匠摊开手掌递出黄铜钥匙；穿浅色雨衣的守门人把戴手套的右手收在胸前；钥匙仍在修表匠掌心里。
- **不应期待：** 守门人已经接过钥匙（第 3 段）、兜帽摘下或真名出现（第 5 段）、下一段的动作。
- **逐项核对：** 谁递钥匙、谁收手、钥匙还在谁手里。三项都答对才算通过；只有两人同框而手部动作含糊不算。

### 2.2 同一人物换装

- **截取段落：** 修表匠换上白围裙之后的行动回合，取该回合第 1 段。
- **画面应出现：** 同一人物仍能认出：短卷发、左眉浅缺口、头肩比例和脸型一致；衣着变为白围裙。
- **不应期待：** 换装被画成另一个人、旧深色短外套仍在、把围裙当成新角色或新身份。
- **对照：** 同一回合分别用参考组 A/B，比较斜侧脸是否让侧脸轮廓更稳定，不改变正面和全身的辨认。

### 2.3 未选择与已选择后的照明

- **截取段落：** 两个回合。选择前取「指尖刚碰到尚未扳下的闸杆」所在段；选择后取闸杆已落下、候船厅三盏灯亮起的段落。
- **画面应出现：** 选择前大厅仍然昏暗；选择后三盏灯亮起，光的方向和范围随行动结果改变。
- **不应期待：** 选择前灯已亮、选择后仍全黑、灯光变化出现在行动生效的段落之前。
- **对照：** 两段使用同一参考组和同一 seed；先看选择前再看选择后，避免记忆影响判断。

### 2.4 线索近景

- **截取段落：** 第 4 段，怀表盖只开一条缝、露出一小截齿轮。
- **画面应出现：** 焦点落在表盖缝和齿轮上，尺寸、金属质感和开合方向清楚，构图是近景或特写。
- **不应期待：** 齿轮的来历、零件来自何处、后续揭晓的地点或人物；画面说明和提示词也不得透露这些。
- **逐项核对：** 画面里能数清是一小截齿轮，不是整只怀表摊开，也不是怀表之外的另一件物品。

### 2.5 遮面到揭晓

- **截取段落：** 第 2 段的遮面形象与第 5 段的揭晓，各取一张。
- **画面应出现：** 第 2 段兜帽遮住脸，只看到浅色雨衣、窄肩和右手手套；第 5 段摘下兜帽，左侧颧骨露出月牙形胎记，人物仍是同一人。
- **不应期待：** 第 2 段提前露出胎记或真名；第 5 段换成长相不同的另一个人；两段的雨衣颜色和肩宽不一致。
- **对照：** 两段使用同一参考组和同一 seed。A/B 只比较斜侧脸是否改善第 5 段的侧脸辨认，不改变第 2 段的遮面。

## 4. 判定规则

- 每个场景按「画面应出现」逐项核对；有一项没做到就是这一行不通过。
- 对照 A/B 时先判断单人辨认和动作，再看斜侧脸是否改善侧脸轮廓；斜侧脸加分不抵消动作或遮面错误。
- 画面说明、提示词、参考图和实际画面分开记录；说明正确但画面错误，仍然不通过。
- 单次样本只写这一行的判定，不据此推算成功率。需要稳定性读数时，同一条件至少重复三次，分别留行。
- 画质、构图和角色能否辨认由维护者人工观看；自动化只负责尺寸、位置、协议、失败和可访问性。
